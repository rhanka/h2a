## Points où un relecteur est corrigé ou nuancé

Aucune remarque n'est écartée. Deux précisions seulement, sans effet sur le fond :

- **Parité FE-0** : la découpe Astra en deux couches est incomplète pour les clés YAML dupliquées (perdues après décodage) ; la v2 retient les trois couches de Sol (structurel / format sérialisé / sémantique).
- **Langue sans catalogue** : le marqueur `untranslated` est bien le capital enregistré (L175), mais en contexte track-report et sous forme de glose ; la v2 le transpose avec résolution au build et garde la forme du marqueur en `proposition-not-validated`, au lieu de le présenter comme un verbatim owner déjà spécifique à Focus.

## Ce que la v2 ne couvre toujours pas (inchangé ou précisé)

- Q1–Q4 restent ouvertes (§8) : force d'une correction, périmètre utilisable vs preuves, arbitrage des divergences (dont l'UX d'arbitrage d'une fourche, §9 n°17), reprise sans le producteur initial. La mécanique de lignée ne tranche aucune de ces questions de principe.
- Forme visuelle/accessible du marqueur `untranslated` et éventuelle politique stricte de build : U9, `proposition-not-validated`.
- Emplacement et durabilité concrets du registre de lignée par consommateur : U7 (FE-5/FE-9).
- Budgets de performance hors profils/corpus/métriques mesurés en phase B : §9 n°12.
- Tout le reste du §9 v1 (tableaux/diagrammes, collaboratif/CRDT, nouveau kind Track, hôte MCP `ui://`, sync multi-machine, etc.) reste NOT covered.
- Aucun code écrit, aucun test de dépôt exécuté, aucune relecture des dépôts aux révisions épinglées : la conformité des lots reste à prouver par leurs RED (commande + sortie), comme l'exigent §6/G1.
- `spec-summary.md` décrit encore la v1 ; il n'est pas mis à jour par cette révision et ne doit pas être cité comme résumé de la v2.
