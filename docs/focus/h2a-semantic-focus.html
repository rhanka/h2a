Le modèle en une page

  • h2a = LA CLI de sentropic — cadre d'organisation centré humain pour agents conversationnels et de code. Axe : CLI/ORG vs LIBS (décision B, repoint stp → h2a).
  • sentropic = les libs (@sentropic/*) : gateway, LLM-mesh, MCP/auth, transport, identité/crypto/NHI, k8s, design-system. N'importent jamais h2a (anti-cycle CI).
  • Un seul plugin déployé = h2a. Les libs restent versionnées à part.
  • h2a offre UN agent : code (≈ Claude Code) + tâches tout-type (≈ délégation « Hermes »). MVP h2a agent run|attach|delegate|logs|wake.
  • Frontière = 3 protocoles neutres owned-architecte : session-protocol, governance-protocol, scope-gate.
  • Rien ne fusionne : track reste record-only, remote reste plateforme autonome.

1 Grammaire de verbes fine

Reco consensus : garder l'adjugé (les 2 pairs convergent). Tu valides ou tu rouvres un verbe précis.

Reco : h2a bus + alias legacy h2a remote (dépréciation douce).

3 agent-stats estate-wide ORPHELIN

Reco : nouveau toit h2a agent stats --all (ou h2a stats — conflit segmentation à arbitrer).

4 Frontière de namespaces

Déport sous host vs deploy ; cond/drum séparés vs gov ; canevas top-level vs nego canevas.

Reco : mcp→host, cond/drum séparés, déport→host, canevas top-level assumé.

5 Scope de init

h2a init = h2a-core par défaut + --all opt-in pour .track+profil dev ?

Reco : oui — pas de seed multi-store silencieux.

6 MVP de l'agent offert

Code + tâches tout-type : réutilise la délégation remote (façon Hermes) ou nouveau runtime ?

Reco : réutiliser remote, pas de nouveau runtime, pas d'auto-conductor au départ.

7 Le nom knowledge

knowledge vs graph vs garder graphify (à trancher avec l'owner).

Reco : knowledge (générique, tool-agnostic) — owner graphify OK sous conditions.

⚠️ Tensions résiduelles (honnêtes)

  • COI structurel (dissidence stp, la plus forte) : faire de h2a le portail de tous crée une incitation long-terme à ses idiomes ; le fallback A (scinder/différer) reste ouvert si un owner non-h2a bloque.
  • agent-stats orphelin par la dépréciation de stp (cf. point 3).
  • Double source de vérité protocolaire : skeletons dérivés vs réel → golden-fixtures + statut experimental jusqu'à ratification owner.
  • Re-key du bus = non purement additif → dual-key transitionnel obligatoire (gated).
  • Vélocité vs design-first : B plus lent que le statu quo fédéré, mais gaté par contract-tests + receipts verts.
  • canevas = +1 namespace (~13→14) alors que la pression est « minimal ».
