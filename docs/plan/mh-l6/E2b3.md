# E2b3 — autres entrées directes, formes shell/nues, eval et sonde legacy

Les quatre API `spawn/spawnSync/execFile/execFileSync` acceptaient les
formes nues `(commande, options/callback)` sans résoudre la commande :
`execFile(imageEntry, cb)` exécutait des octets d'image sans lecteur et
`spawn(imageEntry)` démarrait sans préchargement. `cp.exec`/`cp.execSync`
n'étaient pas wrappés du tout : toute chaîne shell référençant l'image
passait. Les trois trous sont fermés dans `image-execution.js` : les formes
nues résolvent la commande comme une entrée (`image_child_entry_unqualified`
si octets d'image, sinon passage intact), et `exec`/`execSync` refusent les
chaînes shell qui nomment l'image (un shell ne porte pas le préchargement
authentifié). Couverture non déduite du parent : chaque API est exercée
directement, y compris les formes async et nues.

Le refus `exec` async backstoppe aussi par la garde nue `execFile`
(délégation interne de Node, prouvée par mutant) ; `execSync` exige son
wrapper (prouvé par mutant : sans lui il exécute). Les autres entrées
directes natives (`bin`, `boot-worker`, enfants `native-terminal` via
`execFileSync` tableau, préchargeur builtin-only, addon node-pty) restent
couvertes par E1/E2b1/E2b2 (lecteur de module, identité physique, formes
tableau) : les mêmes wrappers patchés s'appliquent à leurs lancements.

Le worker `eval` reste refusé avant évaluation (`image_worker_entry_unqualified`,
verrouillé). L'import tardif reste régi par les hooks de chargement (testé
par la politique : fichier non enregistré sous l'image → refusé). La sonde
legacy charge de vrais octets publiés `.5/.6` (tarball vérifié
`MH_L5_ARTIFACTS`) comme code d'image : refusés `image_module_missing`.
