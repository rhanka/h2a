# E1 — lecture des modules liée au manifeste

Le lanceur installe un lecteur synchrone Node avant l'entrée de l'image.
Tout nouveau module non intégré à Node doit rester dans le root physique
vérifié et figurer au manifeste. ESM, CJS, createRequire, métadonnées de paquet,
modes et octets tardifs sont contrôlés. Les octets vérifiés sont fournis à Node.
Le manifeste du caller est cloné ; le modifier ne change pas cette autorité.
H4 refuse un runtime sans API qualifiée avant même de publier son journal.

Le root s'applique à tous les nouveaux chargements dans ce processus : se fier
au parent déclaré de createRequire permettait de choisir une base externe.
Le rouge `external-base-red` montre ce contournement réel ; le refus global le
ferme. Le lanceur autonome, déjà chargé, reste hors du payload et n'importe
ensuite que les modules Node intégrés et le code de l'image vérifiée.

Les 11 paires couvrent huit points de faute avec plusieurs oracles ESM/CJS et
natif/JavaScript, pas 11 défauts uniques. L'audit exige des rouges observant un
chargement devenu possible (`0 !== 1`), ou le journal devenu possible avant
qualification (`Missing expected exception`), et non une exception de syntaxe.
Les leurres npm parent, HOME et NODE_PATH ne produisent aucun effet.

Le probe exact `node_modules/node-pty` charge sa vraie implémentation et un
addon compilé par le prototype local MH-L0, ouvre une PTY pour son propre
enfant Node puis observe sa sortie. Un octet ajouté au binaire après vérification
est refusé. Sans la garde, cet ELF reste chargeable et le test tue la mutation.
C'est une preuve fonctionnelle de chargement, **pas** la qualification de la
chaîne de release épinglée E3 ; aucune compilation utilisateur n'est ajoutée.

L'oracle initial attendait `image_module_integrity`, alors que node-pty capture
ce premier refus puis termine par son dernier probe absent. L'oracle final exige
exactement l'échec externe observé, `value` absent et le non-succès du probe.
Le log initial étiqueté `final-E1` a été remplacé lors du rejeu : incident
d'archivage du diagnostic. L'ancien oracle a été reproduit séparément dans
`mh-l6-image-policy.test.js-node22-native-oracle-replay.log` (exit 1,
ERR_ASSERTION, un test, zéro skip/enfant), puis les octets du test ont été
restaurés et vérifiés. Ce diagnostic n'est pas une régression produit ni une
preuve rouge/vert. Les vrais rouges d'absence du lecteur, de liaison lanceur,
de qualification préalable et de base createRequire externe restent archivés.
