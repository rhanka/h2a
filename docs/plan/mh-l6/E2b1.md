# E2b1 — vraie entrée directe et routeur npm

L'entrée sélectionnée installe désormais la même garde lorsque Node la démarre
directement, ou lorsqu'un routeur npm .7 l'importe. Un descripteur
`execution.json`, couvert par le manifeste d'image, désigne le préchargeur
externe par son SHA. Le descripteur est fermé, le préchargeur est vérifié
**avant** son import et le contexte installé doit correspondre à l'image.
Il n'y a aucune dépendance circulaire au digest d'image.

La CLI ne charge plus ses modules applicatifs légers avant le routage. Seuls
les modules purs de vérification, leurs builtins et le parseur argv précèdent
la garde. Le routeur met argv[1] à l'entrée absolue sélectionnée et conserve le
PID. Un autre contexte déjà chargé ne peut pas être remplacé dans le processus.
La sélection, les réservations et les refus existants restent autoritaires.
Le chemin non adopté de développement reste disponible ; sa fermeture et les
parcours legacy réels restent à qualifier dans C2/D/E3/F.

Le prototype d'empaquetage fournit le descripteur ; ses fixtures gérées
installent explicitement le préchargeur dans leurs propres I temporaires.
Ce script reste **prototype-only**. Il ne prépare ni le paquet 0.98.7 publié,
ni une chaîne native de release ; les versions core/runtime du checkout
restent 0.98.5 et le paquet enveloppe porte toujours le nom MH-L1 prototype.

Les cinq fautes concernent la liaison du chemin direct, la vérification avant
import, la fermeture du descripteur, argv[1] sélectionné et le chargement du
préchargeur. La mutation du contrôle avant import exécute la première
instruction du préchargeur altéré et crée un témoin : le test exige son absence.
La mutation argv montre le chemin npm au lieu de l'entrée sélectionnée, dans le
même PID. Le mutant sans import est refusé mais casse le parcours nominal :
cette paire qualifie la disponibilité, pas un contournement d'autorité.

Le rouge initial du vrai bin, avant correction sur les deux Node, rapporte
0.98.5 avec un flag `--import` extérieur ; le vert refuse ce profil avant tout
résultat de la CLI. Un tel flag a déjà été traité par Node : ce diagnostic ne
prétend pas annuler du code de préchargement exécuté avant l'entrée h2a.

Les scénarios construits exercent essai préalable, arrêt froid, successeur
réservé, transfert de shim vers le pair externe, checkpoint, ACK perdu et
compensation. Les preuves writer fournies par ces anciennes fixtures ne sont
pas le producteur H4 M18 demandé ; aucun succès M18 n'est déduit de ces tests.
Aucun conducteur live n'est ajouté (option A conservée).

Le test npm conserve deux installations hors ligne, manifeste identique,
shrinkwrap embarqué et vraie PTY via `node_modules/node-pty`. Le cas Node 24 a
été rejoué avec le bin officiel Node 24 en tête du PATH, donc npm 11.19.0 ; le
premier succès sous le PATH initial reste dans la copie privée comme diagnostic.
Ces résultats de snapshot ne qualifient pas tous les chemins d'installation.
