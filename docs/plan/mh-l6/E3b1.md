# E3b1 — construction et qualification des paquets fermés

Les deux vrais noms npm, `@sentropic/h2a` et `@sentropic/h2a-runtime`, peuvent être conditionnés avec cœur/runtime exacts, shrinkwrap effectivement empaqueté et prébuild E3a. Le chemin de release utilise ce prébuild vérifié, jamais le compilateur local du prototype. Les métadonnées de toutes les dépendances sont figées et leurs scripts supprimés. Une garde refuse la publication brute du workspace ; les commandes de publication pointent désormais vers le conditionneur fermé.

Un tarball décrit les deux profils Node 22/24. La préparation copie indépendamment le payload, conserve les octets des liens internes et remplace seulement `manifest.json`, exclusion déjà unique du format, par le manifeste scalaire courant. Elle vérifie les octets capturés avant/après copie, synchronise les fichiers, répertoires et parent, et ne sélectionne rien. L’exclusion maintenue, l’adoption et l’autorité H4 ne sont pas déduites de cette préparation.

Le lecteur lie génériquement le SDK du paquet racine aux dépendances internes, avec les exports/conditions Node réels, y compris `require`. Les leurres parents, bases `createRequire` extérieures et exports privés restent refusés. Aucun nom de MCP, endpoint ou build futur n’est ajouté à une liste fermée.

Chaque vrai paquet est construit deux fois puis installé deux fois hors ligne dans des préfixes neufs, scripts npm activés. Un contrôle positif distinct exécute réellement un postinstall. Les compilateurs leurres ne sont jamais exécutés par la release ; la mutation de fallback exécute leur première instruction et échoue. Le test historique MH-L1 conserve sa compilation locale de faisabilité et son ancien profil ; il ne qualifie pas la chaîne de release.

Les modules d’upgrade effectivement publiés .5/.6 sont comparés aux octets de leurs tarballs avant import ; seules leurs méthodes `stageInstall`, `probeStagedVersion` et `verifyStagedNative` sont appelées, avec des préfixes temporaires. Elles installent le vrai tarball .7, trouvent sa version et chargent le vrai addon ; un ELF rendu invalide est refusé. Aucun swap, préfixe réel ou h2a installé n’est invoqué.

Le transport corrigé installé est exercé avec IDs numérique/texte réutilisés et réponses différées. Le même tarball produit sous Node 22 est préparé puis charge le vrai SDK et le PTY sous Node 22 et Node 24. Ses manifestes concordent avec ceux de la construction Node 24. Le conditionneur vérifie aussi une installation npm réelle de son tarball : npm omet `.bin` dans l’archive et régénère ces liens à l’installation ; aucune exclusion de code n’est ajoutée.

Audit exécuté : `node scripts/mh-l6-e3b-audit.mjs /tmp/mh-l3-qualification-YeHHOv/source`, exit 0 : 43 sources identiques, sept dist, 148 tests et 37 paires par profil, deux payloads et lanceur/préchargeur reproduits. Les commandes npm finales utilisent **npm 9.2.0 sous Node 22**, **npm 11.19.0 sous Node 24** ; les sorties `npm --version` sont dans la preuve.

`proof-E3b.json` et le script d’audit lient sources, dist, reçus, mutations restaurées, nouveaux lanceur/préchargeur autonomes et reconstruction des deux payloads. La réparation du shim du prototype, détectée par les huit références d’entrée, est vérifiée séparément ; l’audit reconstruit ensuite les arbres release et compare leurs manifestes complets aux artefacts npm déjà exercés.

## Diagnostics exclus de la preuve finale

Les premiers essais ont détecté l’absence d’API, un mauvais oracle de message, puis une annulation de fixture esbuild : aucun ne compte comme vert. Le validateur nouvellement écrit omettait le dernier `node_modules` racine ; l’hypothèse d’un défaut du placement a été réfutée par mutation et cette modification a été retirée. La tentative de duplication excessive, refusée sur la taille de sortie, est abandonnée. Les liens réécrits par défaut par `fs.cpSync` et l’absence de sync du parent ont leurs rouges/verts propres.

Un premier oracle de fsync ne distinguait pas fichier et parent ; sa mutation survivait. Il cible maintenant les fichiers réguliers, avec un oracle distinct pour le parent. Le rejeu historique du lecteur s’arrêtait sur une ancre devenue obsolète après E2a ; il vise désormais la vraie installation de la politique d’exécution et conserve ses onze paires. La garde de sélection n’a jamais été assouplie pour réparer le shim du prototype.

## Périmètre encore ouvert

**E3b2 est obligatoire avant de clore E3b.** La publication distante/OIDC, le workflow smoke qui empaquette encore les workspaces bruts, le test historique de non-distribution du seam et les diagnostics d’installation hors profil ne sont pas qualifiés par ces 148 tests. Le paquet de qualification porte encore des restrictions npm Linux/x64 : elles doivent être remplacées par le refus de mutation H4 sur les profils non qualifiés, en conservant l’accès aux diagnostics. Ce sont des écarts ouverts, pas des exceptions acceptées. Les anciens tags dépourvus des nouveaux outils de release restent aussi à traiter dans l’intégration CI.

Les artefacts .7 sont des candidats de qualification. Le bump final de toutes les métadonnées suit la politique de branche à la fin de MH-L6 ; aucun tag ni publication npm n’a eu lieu. E2b3/E3c restent requis pour les autres vraies entrées natives, la sonde gérée, le gel .6 ou les relancements U07/U11. B2/C2b/D/F/M18 restent ouverts. Ni adoption, ni fermeture maintenue des writers v1, ni performance/endurance, ni release/FUSIONNABLE ne sont revendiquées. glibc effectivement exécutée : 2.43 ; baseline 2.31 ciblée seulement.
