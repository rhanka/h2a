# MH-L4 source contracts for MH-L3

Frozen API/schema version: 1. Base c8a11016 (MH-L2 reviewed). This lot supplies source participants; MH-L3 supplies logical attachment/transport correlation, transfer proof consumption and catalogue changes. Product acquisition/restoration and live coordination remain .8. QF A+B and QC outside latest remain in force. No release metadata changes.

| API | Contract |
|---|---|
| Participants.attach(attachmentId, context) | Called after authenticated admission; persists ownership before activation. MH-L3 supplies the stable logical attachmentId rather than deriving it from HTTP transport IDs. The current adapter allocates a private source ID; its inventory says pending-MH-L3. |
| AttachmentParticipant.runOwner(fn) | Runtime context only, never a public JSON-RPC field. Owner writes re-read generation/epoch/full process tuple and state inside the common mutation lock. Presence also binds the exact session and instance. |
| AttachmentParticipant.call(fn) | Atomically admits an independent operation before execution. Nested same-attachment calls reuse that right. The central protocol retains it through formatting and recovery-payload persistence, before reply delivery. A barrier rejects new rights. Already-admitted operations can finish their business work while owner presence/heartbeat/wake/delegation is fenced. |
| Participants.barrier / freeze / checkpoint / abort | Bound to handoverId. Barrier closes conforming generic writers and stops owner scanners/heartbeats. Freeze refuses active callbacks or pending attachment activation; unknown effects stay durable and keep drain blocked. Abort reopens only after the component journal is durably ABORTED. |
| OwnershipRegistry.fence(token,handoverId,checkpointHash) | Source-only transition FROZEN→TRANSFERRING, idempotent, exact checkpoint binding. Abort cannot reopen it. Caller MH-L3/.8 must authenticate concordant publication first; no product live route calls it here. |
| OperationLedger.finish | Durable owner-directed event precedes completion. Unknown outcome remains counted; it is never converted into an instruction to replay. Events identify current-owner destination and operationId; digest(event) deduplicates delivery/reconciliation. |
| Participants.drain | Revisioned calls/children/briefs/callbacks/effects; live central additionally counts HTTP calls and transport callbacks. launching is a response, never completion. No 60s kill or pipe/supervision transfer. |
| LaunchJournal | Key attachmentId+launchName; digest binds initial arguments. Memo reservation precedes spawn; private launch token reaches the actual async runtime. Same key/args returns/reconciles; incompatible args conflict through both memo and MCP cache. |

Ownership and checkpoint retain the MH-L0 closed formats. Ownership is keyed by a digest-addressed filename and carries ACTIVE/FROZEN/TRANSFERRING/CLOSED, source identity, epoch, handover, presence binding and checkpoint hash/version. Records live in the private L2 stateDirectory; the common writer exclusion lives in root/.h2a-writer-control. Public callers never reconstruct a filename from an untrusted ID.

Checkpoints are immutable canonical JSON, fsynced before their ownership hash is recorded. References are checkpoint-<sha256>.json, bound to attachmentId/ownershipEpoch. loadCheckpoint validates schema, canonical bytes, path and hash. Same checkpoint after lost ACK returns the same receipt; changed payload conflicts. A snapshot above 4 MiB refuses instead of truncating. Snapshot fields cover captured context, resolved identity, presence, actual negotiated downstream protocol, served catalogue, subscriptions, peer/inbox baselines, notifications/owner effects, negotiation count/hash and truncation, blockages, produced/delivered sequence, separate wake seen/intents, terminal/delegation references and launch memos. The empty-attachment checkpoint preserves L2's format and requires complete drain.

Notification delivery means transport completion only. The dispatcher stores stable event digests and production sequences, advances contiguous deliveredSequence only on actual delivery, and always preserves applicationAcknowledged:false. It does not invent a CLI-consumption ACK. MH-L3 must carry/authenticate these sequence receipts to its shim transport and provide the peer restoration consumer. No product restoration implementation exists in this lot.

Wake baseline is separate from notification baseline. Ordinary initial boot seeds seen from inbox; a qualified transfer may supply restoredSeen. Intention and possible effect are persisted before injection. Concurrent invocations serialize. Deferral false is a proven non-injection and may retry with a fresh signed line, persisted before the new attempt; thrown/lost receipt is unknown and suppresses each affected envelope, even when new envelopes arrive or the handler restarts. A fresh nonce is not used to replay an unknown wake.

Launch receipts reuse runs/<name>/launch.json under the captured workspace. launchReceiptReference is relative to that immutable workspace root; a private launchLocation record retains the binding and nullable delegation parameters before spawning. Receipt token must hash to launchTokenBinding. A stopped receipt closes outstanding creation/brief work. The inherited started receipt does not prove brief delivery; the brief stays unknown unless the full returned runtime result attests prompt.delivered:true. Reconciliation never spawns, briefs or kills. A final memo written before ledger closure is re-read to publish the durable, idempotent current-owner delegation event before closing missing operations. Publication/closure failure keeps drain blocked until reconciliation. Independent shims do not share a deduplication key.

Eligibility requires a trusted internal writerProof {evidenceDigest,verify}; verify is re-run at reserve, barrier, freeze and commit. It must prove current extinction/reconciliation plus maintained closure of legacy admissions and qualified future routing. There is no CLI/MCP flag to assert qualification. Missing proof→store_writer_set_unknown; legacy admission→legacy_writer_unfenced. MH-L6/MH-L8 produce/qualify actual installation admission proof. Tests inject private maintained fixture proofs; no process scan is presented as such proof. Historical use alone neither grants nor permanently denies eligibility. See WRITERS.md for the writer audit and Linux flock profile prerequisite.

Source integration exposes the existing authenticated L2 administrative routes. BARRIER filtering parses exact JSON-RPC methods (including batches); a cancellation string inside tool arguments cannot admit new work. Commit-stop remains internal, irreversible and target/precheck-authorized by L2. No native restart, live coordinator, release publication, schema migration or legacy retrofit is delivered.

Qualification limits: MH-L5 owns full M17 and comprehensive cut matrix; MH-L8 owns real Claude, exact images/Node profiles, load/endurance and cross-host independent review. Local review critiques are recorded separately and are not an author-complementary consensus verdict.
